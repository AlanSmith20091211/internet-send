# Internet Send 产品方案

> 版本：v0.1 起步方案 · 2026-10

## 1. 要解决的问题

日常高频场景：**同一个 Wi-Fi 或同一个手机热点下，几台设备（手机 ↔ 电脑、电脑 ↔ 电脑、安卓 ↔ iPhone）之间临时传文件/传一段文字**。

现有做法的痛点：

| 做法 | 痛点 |
| --- | --- |
| 微信/QQ 文件传输助手 | 走公网，慢、耗流量；有大小限制；图片视频被压缩；需要登录同一账号 |
| 网盘 | 先上传再下载，两倍时间；限速；需要外网 |
| 数据线 / U 盘 | 需要线和驱动，iPhone ↔ Windows 尤其麻烦 |
| AirDrop / 快传 / 互传 | 被锁在单一品牌生态里，跨品牌（苹果 ↔ 安卓 ↔ Windows）不通 |
| 开源同类（LocalSend、PairDrop 等） | LocalSend 每台设备都要装 App；PairDrop 类网页方案依赖公网信令服务器，纯热点无外网时不可用 |

**我们的定位：跨品牌、不走公网、接入门槛最低（扫码即用）的局域网传输工具。**

## 2. 目标用户与场景

1. **个人多设备用户**（核心）：手机拍的照片/视频传到电脑、电脑上的文件发到手机、在两台电脑间同步一段文字/链接。
2. **办公小团队 / 会议室**：同一间会议室内把文件发给所有人，不需要互加好友。
3. **无网 / 弱网环境**：出差、户外、实验室、机房——只有一个手机热点，没有可用外网。
4. **教育 / 培训**：老师把资料一次性发给教室里所有学生设备。

## 3. 产品原则

1. **接入最少一步**：至少一端不需要安装任何东西（浏览器扫码）。
2. **完全离线可用**：不依赖任何公网服务（包括 CDN、信令服务器、账号系统）。
3. **跨所有平台**：Windows / macOS / Linux / Android / iOS / 鸿蒙，一视同仁。
4. **原画质、无大小限制**：不压缩，大文件不爆内存，可断点续传。
5. **默认安全**：数据不出局域网；公共网络下一键开启口令/配对；后续加密传输。

## 4. 技术路线

### 阶段一：Hub 模式（当前 v0.1）

```
主机（电脑）: Go 单文件程序 = HTTP 服务 + 内嵌网页
其他设备: 浏览器访问 http://<主机局域网IP>:8787
实时: SSE   上传: 流式 POST 落盘   下载: HTTP Range
```

- 选择 **Go**：单二进制、交叉编译简单、零运行时依赖、并发模型适合长连接，后续也能直接作为桌面端/手机端的内核（gomobile）。
- 选择 **原生 JS 无构建**：网页足够简单；必须内嵌、离线可用；降低贡献门槛。
- 已知局限：文件经主机中转（主机磁盘留存一份）；主机必须是电脑；浏览器在 HTTP 下无法使用剪贴板 API、通知 API 等安全上下文能力。

### 阶段二：发现与直连

- **自动发现**：主机通过 mDNS/DNS-SD（`_internet-send._tcp`）+ UDP 组播广播自身；原生客户端无需扫码自动出现在列表。
- **WebRTC 点对点**：主机只做信令，浏览器之间用 DataChannel 直传，不再经过主机磁盘；失败时回退到中转。
- **HTTPS（自签证书 + 证书指纹二维码）**：解锁剪贴板、通知、Service Worker（PWA 可"安装"到手机桌面）。

### 阶段三：原生客户端

- **桌面端**（Wails / Tauri 包一层壳，复用 Go 内核与网页 UI）：托盘常驻、开机自启、右键菜单「发送到…」、系统通知、自动接收。
- **移动端**（Flutter 或原生 + gomobile 内核）：手机也可做主机、系统分享菜单「用 Internet Send 发送」、后台接收、相册直接保存。
- 协议向前兼容：原生端与浏览器端可以互通。

## 6. 衡量指标

- **首次成功传输耗时**（从下载程序到第一次传成功）：目标 < 60 秒
- **连接成功率**（扫码后成功上线 / 扫码次数）：目标 > 95%，失败原因分类（AP 隔离、防火墙、VPN 网卡）
- **传输速度**：5GHz Wi-Fi 下达到链路带宽的 70% 以上
- **留存**：周活跃设备数、人均周传输次数
- 获取方式：产品本身不做任何联网上报；采用 GitHub Release 下载量、用户自愿反馈、可选且默认关闭的匿名统计（v1.0 再议）。

## 7. 商业化思路（远期，先做口碑）

- **免费核心**：个人使用的全部传输功能永久免费，这是口碑和增长的基础。
- **Pro（个人买断/订阅）**：多设备剪贴板同步、自动同步文件夹、传输历史搜索、自定义主题。
- **团队/教育版**：会议室/教室模式（一键分发给所有人、收作业）、管理员控制、审计日志、私有部署。
- **硬件/OEM 合作**：嵌入 NAS、路由器、电视盒子固件。
- 开源策略需要尽早决定（影响社区与商业化）：建议核心协议与主机开源（MIT/Apache-2.0 获取信任与贡献），原生 App 的 Pro 功能闭源。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 路由器 AP 隔离 / 访客网络导致设备互不可见 | 连接失败时给出明确诊断提示；推荐手机热点；远期提供"主机开热点"模式 |
| Windows 防火墙拦截 | 文档 + 首次启动提示；桌面安装包里自动添加专用网络规则 |
| 局域网内被他人访问 | 公共网络默认开口令（v0.2 起检测到公共网络自动开启）；v1.0 设备配对 + 端到端加密 |
| 同类产品竞争（LocalSend 等） | 差异化：免安装扫码接入 + 纯离线 + 中文用户体验（鸿蒙、国产安卓的适配） |
| iOS 浏览器后台限制（锁屏断开） | 网页端提示保持前台；iOS App 解决后台接收 |
